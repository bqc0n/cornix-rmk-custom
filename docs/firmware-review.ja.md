# ビルド修正とファームウェア点検（2026-10-03）

対象は Cornix のローカル設定、LED 実装、ビルド／UF2 生成処理と、固定した RMK の
左右通信・キー処理・フラッシュ初期化です。実機への書き込みや無線試験は行っていません。

## 修正した問題

### 非同期マトリクスのコンパイルエラー

元の依存先 `00a42c35cc8b60e1b331c4c1226a906d9e81b6d4` は、マトリクスと
direct-pin の待機処理４箇所で `select_slice(pin!(futs.as_mut_slice()))` を呼びます。
これは Future のスライス自体ではなく、スライスへの参照を pin するため、
`Pin<&mut &mut [Future]>` と要求される `Pin<&mut [Future]>` が一致せず E0308 になります。

[上流修正 a41b338d](https://github.com/HaoboGu/rmk/commit/a41b338da87ce0455217ff44e92d187233d6a867)
は待機 Future を配列で保持し、`select_array` に所有させます。これを含むリビジョンに
Cargo.toml と Cargo.lock を更新しました。`async_matrix` は有効のままです。
従来の充電器接続時の USB 修正も含まれています。

このリポジトリが最新でも、Cargo.toml の `rev` は RMK のその時点のコミットを固定します。
`main` の後続変更は自動では入りません。今回は最新 HEAD への一括更新ではなく、
該当修正までの更新です。間にある nRF 向け変更はコンボのキー押下状態修正です。
ビルドと objcopy に `--locked` を追加し、確認済みの依存関係で生成します。

### 設定ファイルの変更検知

build.rs は常に `keyboard.toml` を監視・ハッシュ化していました。一方 RMK マクロは
`KEYBOARD_TOML_PATH` を読みます。別ファイルへの切替やその内容変更が Cargo に検知されず、
再利用するビルドディレクトリによっては古い設定が残る問題があります。
監視・ハッシュ化を実際の設定パスに揃え、環境変数の変更も監視しました。
設定ファイルが読めない場合はビルドを失敗させます。
既存のリセット専用ターゲット分離は維持しています。

### 説明と設定の不一致

保存領域の説明は `0xA0000..0xA8000` となっていましたが、32 × 4096 バイトなので
正しくは `0xA0000..0xC0000` です。実際の設定値は正しく、コメントを修正しました。
また tap-hold は `permissive_hold` と flow-tap、hold/gap は 400ms です。
「別キーを押した瞬間に hold」「1500ms」という README の記述を訂正しました。
Vial の保存済み設定は、この初期値より優先されます。

## 重大な未解決リスク

### 右側の押下中に split BLE が切れると、キーが残る可能性

右側から受信したキーイベントは左側のキーボード処理に発行されますが、
左右のリンク切断時に右側の押下を解除する処理は見当たりません。
`PeripheralConnectedEvent` は通知されますが、キーボード処理自体はこれを購読していません。
右側のマトリクスは切断中も動作するため、その間に離したキーの release が左側に届かず、
再接続時も全押下状態の同期がありません。

通常キーの連続入力、Shift/Ctrl の残留、MouseBtn3 のドラッグ継続、MO のレイヤー残留が
想定されます。ソースからの推論であり実機再現は未確認ですが、通常運用前に優先して
検証すべき問題です。ビルド修正だけでは解消していません。

根拠:
[split/driver.rs](https://github.com/HaoboGu/rmk/blob/a41b338da87ce0455217ff44e92d187233d6a867/rmk/src/split/driver.rs)、
[split/ble/central.rs](https://github.com/HaoboGu/rmk/blob/a41b338da87ce0455217ff44e92d187233d6a867/rmk/src/split/ble/central.rs)、
[split/peripheral.rs](https://github.com/HaoboGu/rmk/blob/a41b338da87ce0455217ff44e92d187233d6a867/rmk/src/split/peripheral.rs)、
[keyboard.rs](https://github.com/HaoboGu/rmk/blob/a41b338da87ce0455217ff44e92d187233d6a867/rmk/src/keyboard.rs)。

再現試験: 無害な入力先で右側の文字、修飾、マウスボタン、レイヤーキーをそれぞれ保持し、
右側を電源断する。切断後にホストの押下状態が解除されるか確認し、右側のキーを離してから
再起動して復帰も確認する。修正には split の受信側で押下を追跡し切断時に解除する処理と、
再接続時の同期が必要です。通常動作への影響が大きいため今回の修正には含めていません。

## その他の注意点

- `*-reset.uf2` は毎回の起動でキーマップとボンドを消去します。初回起動後は通常版を
  書き戻す必要があります。通常版の展開結果は `clear_storage: false` と確認しました。
- LED の「充電」は VBUS の検出です。充電 IC の状態や充電完了の検出ではなく、
  残量 95% 以上の緑表示も実際の満充電を保証しません。
- `LedIndicatorEvent` は USB からも発行されるため、USB 接続時に BLE 接続表示を
  誤って点灯させる可能性があります。入力処理への影響はありません。
- LED は消灯中も約 33ms ごとに起床します。DMA は色が変わるときだけですが、
  バッテリー駆動時の消費電流は実測が必要です。
- LED の複数表示が同じ `frame` を使うため、別の状態変化で表示期間が再開することがあります。

## 確認結果

- `cargo make uf2` と `cargo make uf2-reset` は左右とも成功。
- UF2 の magic、ブロック番号／個数、nRF52840 family ID、書き込み範囲、初期 SP と
  Thumb の reset vector を確認。通常版の書き込み範囲は左 `0x1000..0x6F800`、
  右 `0x1000..0x47900`（終端は含まない）。
- リンカーの FLASH 範囲は `0x1000..0xA0000`。保存領域 `0xA0000..0xC0000` と
  想定の Adafruit ブートローダー開始 `0xF4000` に重なりません。
- 展開した中央コードで `num_sectors: 32`、`start_addr: 655360`（`0xA0000`）、
  `clear_storage: false` を確認。DFU に関する上流の警告は出ますが、このビルドは
  `dfu_nrf` を有効にしておらず、実際に生成される保存開始アドレスは指定どおりです。
- ELF の `.data` + `.bss` + `.uninit` は左 55,276 バイト、右 31,756 バイト。
  リンク時の RAM オーバーフローはなく、flip-link によるスタック保護は有効です。
- 別設定ファイルの内容変更で生成 fingerprint が変わること、パス・環境変数が監視されること、
  設定が存在しない場合に build.rs が失敗することを確認。

基板の実際のブートローダー、電源回路、バッテリー分圧、無線切断・復帰、入力遅延は
実機未検証です。フラッシュ破壊につながる配置の衝突は今回の確認範囲では見つかりませんでした。
